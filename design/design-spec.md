## 0. 最初に伝えたいこと

1. **AI は追加費用なしで組み込めます。**【事実】Apple の Foundation Models フレームワーク（端末の中で動く Apple 製の AI を、アプリから呼び出す仕組み）は、Apple Intelligence が対応する言語で読み書きでき、日本語が入っています [A1][A2]。【二次情報】端末内で動くため利用ごとの料金がかかりません [B1]。
2. **AI が動く機種は限られます。**【事実】iPhone 15 Pro／15 Pro Max、iPhone 16 以降、iPhone Air、iPhone Duo、M1 以降の iPad と Mac など [A2]。Shogo さんの iPhone 17 Pro Max は対象です。非対応の機種では AI の機能を出さず、「記録」と手入力だけで成り立つようにします。
3. **Google カレンダー連携は、最初は iPhone の設定に登録済みのカレンダーを使う方式です。** Apple の EventKit（カレンダーを読み書きする公式の仕組み）経由で、Google・iCloud・Outlook をまとめて扱います。直接つなぐ方式は、【事実】カレンダーの予定を読む権限が Google の審査対象で、審査の目安は3〜5営業日です [G1]。後回しにします。
4. **「何でもできる」は伝わりにくいので、入口の言葉を1つに絞ります。**【推測】ストアでの一言は「予定も、推し活も、収支も。写真で残せるカレンダー」。
5. **競馬・競艇・FX の扱い。**【二次情報】Apple の審査の決まりは「実際のお金を賭ける遊びを提供するアプリ」に免許などを求めるものです [B5]。このアプリは記録をつけるだけで、購入・予想の販売・賭けへの誘導はしません。【不明】審査の決まりの原文は今回読めていません。【推測】記録だけなら対象外と考えますが、審査で聞かれたら「記録専用」と説明できる作りにします（外部の投票サイトへのリンクを置かない、など）。
6. **「推しの情報を自動で拾う」は第2弾のままです。**【推測】自前のサーバーと、情報元の利用条件の確認が要るためです。
7. **売れるかは未検証です。**【二次情報】Fantastical は月1,000円・年10,000円、TimeTree プレミアムは月300円・年3,000円 [B2]。標準カレンダーは無料です。価格は 年額4,800円／月額500円／買い切り9,800円 の3本立てに決定（2026年11月11日）。
8. **アプリ名「ペタカレ」は仮称です。**【不明】商標と App Store での重複は未確認。

### A-3. AI の使いどころ

```
入力（文章／写真／PDF）
  → ① 文字にする（写真は Vision、PDF は PDFKit）
  → ② 日時・金額のあたりを付ける（NSDataDetector と正規表現。AI ではない）
  → ③ 端末内AIで決まった形に直す（予定の候補 または 記録の下書き）
  → ④ 画面に出して人が確かめる（自動では保存しない）
  → ⑤ 予定は EventKit、記録は SwiftData に保存
```

- 記録の下書き：的中画面や取引履歴の写真から、日付・金額・プラスかマイナスか・種目の候補を読み取ります。金額はまちがいが困るので、必ず確認画面を通します。
- 「来週」「18日」などの日付の補完と、金額の合計は、AI ではなくアプリ側の計算で行います。
- AI が使えない機種では②だけで下書きをつくります（回数に数えない）。
- **実装済み（バージョン 0.8.0）**：予定の取り込みで、端末内AI が題名を整え、場所を探します【事実：使った仕組みは Foundation Models の `SystemLanguageModel`・`LanguageModelSession` [A7][A8]】。AI の答えは「題名: …」「場所: …」の2行だけを受け取り、アプリ側で確かめてから画面に出します：題名は40文字まで、**場所は元の文章にその言葉が書いてあるときだけ採用**（AI が場所を作り出せないようにするため）。日付・時刻は今までどおりアプリの計算です。候補のそばに「AIが読み取った結果です」と出し、「AIの読み取りを取り消す」で機械的な題名に戻せます。人が直した題名は上書きしません。【不明】日本語での読み取りの良し悪しは、自動チェックのシミュレータでは AI が動かないため未確認（実機で確認が必要）。
- 内容は端末の外に送りません（iCloud 同期は利用者自身の iCloud）。

### A-4. 部品の分け方と状態管理

状態は Swift 標準の Observation（`@Observable`）。外に触る部分は窓口（protocol）で包み、テストで差し替えます。

| 部品 | 役割 |
|---|---|
| `CalendarStore` | EventKit の読み書き |
| `RecordStore` | 記録と写真の保存・検索・同期（SwiftData） |
| `TextExtractor` | 写真・PDF → 文字 |
| `DraftGenerator` | 文字 → 予定の候補／記録の下書き（端末内AI／簡易） |
| `DateResolver`・`SlotFinder`・`StatsCalculator` | 日付の補完、空き時間、集計と予算（AIなしの純粋な計算。そのままテスト） |
| `PhotoGrouper` | 写真を撮影日ごとに分ける |
| `LockGate` | ロックの状態（アプリを閉じたら再ロック） |
| `SummaryRenderer` | まとめ画像をつくる |
| `QuotaStore`・`EntitlementStore` | 無料回数、Pro かどうか |

画面ごとの状態：`CalendarModel`、`RecordListModel`、`RecordEditModel`、`StatsModel`、`CaptureModel`、`ShareModel`、`SlotModel`、`PaywallModel`。

### A-5. データ構造

```swift
@Model final class Record {              // 記録（SwiftData・iCloud 同期）
    var id: UUID
    var day: Date                        // その日の0時
    var kind: String                     // balance（収支）/ oshi（推し活）/ free（自由）
    var category: String?                // 種目や推しの名前（FX、競馬、競艇、…。自分で追加できる）
    var amount: Int?                     // 円。プラスは収入、マイナスは支出
    var title: String
    var memo: String
    var photos: [RecordPhoto]
    var createdAt: Date
    var source: String                   // manual / share / bulk / ai
}
@Model final class RecordPhoto { var id: UUID; var takenAt: Date?; @Attribute(.externalStorage) var data: Data }
@Model final class Budget { var category: String; var monthlyLimit: Int }   // 予算（Pro）
@Model final class CaptureRecord { ... }   // 取り込みの履歴（第1稿と同じ。取り消し用）

struct EventDraft { ... }                // 予定の候補（第1稿と同じ）
struct RecordDraft { var dayText: String; var amount: Int?; var category: String?; var title: String }
struct MonthStats { var balanceTotal: Int; var byCategory: [(String, Int)]; var plusCount: Int; var minusCount: Int; var oshiSpent: Int }
```

予定そのものはアプリ内に複製しません（EventKit が正）。金額は整数の円だけを扱います（小数・外貨は最初のバージョンでは扱わない）。

#### 色分け（設定 → 色分け）

予定と記録の色を、50色の中から自分で選べます。色の雰囲気を丸ごと変える「見た目」の切り替え（スタイリッシュ／かわいい）は作りません（本人の判断で取りやめ）。

- **50色の中身**：10系統（赤・オレンジ・黄・緑・青緑・青・紫・ピンク・茶・グレー）× 5つの調子（あざやか・明るい・うすい・こい・くすみ）。どの色にも「ピンク・あざやか」のような名前があり、VoiceOver で読み上げます。ライト用とダーク用の値を別に持ちます。値は `design/build.py` の `preset()` が正です。
- **色を付けられる単位**：
  1. カレンダーごと（仕事、家族など）。最初は端末のカレンダーの色（「元の色」）。
  2. 記録の種類ごと（推し活、収支・FX、日々の記録など。自分で追加した種目も）。
  3. 予定1件ごと（S-02 の予定のシートに「色」の行を足す）。選ばなければカレンダーの色。
- **選び方**：一覧で行をタップ → 色のシート（50個の丸）→ タップで選ぶ → 右上の完了。シートの下に、月の帯になったときの見本と「最初の色に戻す」（カレンダーは「元の色に戻す」）。
- **保存先**：選んだ色はこのアプリの中に保存し、iCloud で全端末にそろえます。元のカレンダー（Google など）の色は書き換えません。
  - 事実：端末のカレンダーの仕組み（EventKit）では、カレンダーの色（`EKCalendar.cgColor`）は読み書きできます [A6]。
  - 確認できた範囲：予定1件ごとの色を持つ項目は、読んだ資料（`EKCalendarItem` の一覧。一部のみ表示）には見当たりません。全項目は未確認。
  - このため、予定1件ごとの色は Google カレンダー側の「予定の色」とは連動しません（Google で付けた予定の色は読めず、こちらで付けた色も Google には出ません）。
- **色だけに頼らない**：帯には必ず題名が入り、一覧にはカレンダー名・種類の名前が出ます。収支の＋／−は記号でも示します（これまでどおり）。
- **無料／Pro**：50色すべて無料（提案）。
- **データ**：`ColorChoice`（対象の種類：カレンダー／記録の種類／予定、対象のID、色の番号 0〜49）を SwiftData に持ち、iCloud で同期。色の番号と値の対応表は PetaCore に置いてテストを付けます。

#### 集計のグラフ（S-11）

- 日ごとの収支（棒＝その日の合計、点線＝月初めからの積み上げ）、種目ごとの合計（横棒）、月ごとの収支（6か月）。

- どのグラフも題と要約の文を付け、棒は0から。プラスとマイナスは色に加えて＋／−の記号と数字で示します。VoiceOver は棒ごとに「7日 +2,200円」のように読みます。

#### かんたん入力（S-15。長押しで予定を入れる）

- **開き方**：月の画面で日を長押し、週・日の画面で時間のところを長押し。同じ画面は右上の ＋ からも開きます（長押しだけの操作にしない決まりのため）。
- **最初の値**：月で長押し → その日の「終日」。週・日で長押し → 押した時刻（30分きざみ）から1時間。＋ → 今日なら次の正時、ほかの日は 9:00。
- **題名の欄**：開いたらすぐ入力できます。「明日15時 打ち合わせ」のように日時の言葉を入れると、日時を読み取って下の行に反映し、題名からはその言葉を外します。読み取った内容は欄のすぐ下に文で出し、行をタップすれば自分で直せます。読み取りは PetaCore の計算（`JapaneseDateParser`）で、AI は使いません（回数の制限なし・無料）。
- **行**：開始、終了、終日、カレンダー（保存先）、色（50色。選ばなければカレンダーの色）。
- **くわしく設定**：場所・くり返し・通知などは、入力した内容を引き継いで iPhone 標準の編集画面を開きます。
- **実装**：バージョン 0.3.0。開始・終了は iPhone 標準の日時の部品。
- **保存**：右上のチェック。題名が空なら「（題名なし）」ではなく保存ボタンを無効にします。入力があるのに閉じるときは「変更を破棄」「キャンセル」で確認。
- **状態**：カレンダーの許可がないときは長押し・＋とも無効（S-01 の案内を表示）。書き込めるカレンダーが1つもないときは「書き込めるカレンダーがありません」と表示。
- **アクセシビリティ**：長押しには VoiceOver のアクション「予定を追加」を付けます。

#### Google の色について（調べた結果）

- 事実：Google カレンダーの仕組み（Calendar API）には、予定ごとの色番号（`colorId`）と、番号から色の値を引ける一覧があります [G2]。カレンダーごとの色も同じ一覧で引けます。
- 事実：それを読むには、アプリから Google に直接ログインしてもらう必要があり、予定を読む権限は Google の審査（確認）が必要な種類です [G1]。審査の目安は 3〜5 営業日と書かれています。
- 今のアプリは iPhone に登録済みのカレンダーを読む方式で、こちらで取れるのはカレンダーごとの色だけです（予定ごとの色は取れない。A6 と「読めていないもの」を参照）。
- 選択肢：
  1. 今のまま（カレンダーごとの色＋アプリ内の50色）。追加の作業なし。
  2. 「Google と直接つなぐ」を足して、予定ごとの色も取り込む。必要なもの：Google Cloud でのアプリ登録、プライバシーポリシーのページ、Google の審査、ログイン画面、予定の読み込みと突き合わせ（iPhone 側の予定と同じものを見分ける処理）。自分のサーバーは使わず、端末から直接読む形にできます（推測：端末だけで完結できるかは実装時に確認）。
- 推奨：2 を「Google の色を取り込む（任意の設定）」として、記録の段階のあとに入れる。最初のバージョンの必須にはしない（審査待ちで公開が止まらないようにするため）。未確定。

### 4. プラットフォーム別

**iPhone**：題名の下に「日／週／月」の切り替え。月は画面いっぱいの格子で、1日に予定の帯を3本まで（入りきらない分は「ほか○件」）、その下に記録の印（四角）と金額。日をタップすると、その日の予定と記録が下からシートで出る（大きさを変えられるので、つまみ付き）。予定をタップすると S-02 のシート。最大文字サイズでは「日」の表示を既定にし、月の帯は題名を出さず本数だけにする（**このときのモックは作り直していません**）。S-10 の行は、最大文字サイズで金額を題名の下の行に移す。

**iPhone Duo**：外側は1段（月の金額は省き、点だけ）。内側の横向きは左に月（金額つき）、右に日の一覧。半分折ったときは左右均等で、中央 ±13pt に何も置かない。内側の Split View（画面の半分）では外側と同じ1段。バーの位置は近似。あふれるときは ＋ → タブ → 検索 → 候補日 の順に残す。

**iPad**：横向きは月の格子（予定の題名と記録の金額の帯）＋右に日の一覧。細いウィンドウでは点の表示にして一覧を下へ。キーボード：⌘N 記録を追加、⇧⌘N 予定を取り込む、⇧⌘V クリップボードから取り込み、⌘T 今日、⌘F 検索、⌘1〜⌘4 タブ。メニューバーの「表示」に各タブ。

**Mac（ネイティブ）**：メニューバーは ペタカレ → ファイル → 編集 → 表示 → ウインドウ → ヘルプ。サイドバーに カレンダー／記録／集計。設定は「設定…」（⌘,）の別ウィンドウ。ツールバーは1行（題名と今月の合計、今日、候補日、＋、検索）。ウィンドウの最小は 800×560pt（狭いと右の日の一覧を先に隠す）。ロックは Touch ID かパスワード。ショートカットは iPad と同じ。

**実装とモックのちがい（バージョン 0.9.0）**：
- 2列にするかどうかは端末の種類ではなく幅で決めます（使える幅が 700pt 以上で、月＋その日の一覧）。月の側が 560pt より狭いときは、帯ではなく小さい月（点と金額）にします。
- iPhone Duo の内側は、折り目の位置を OS から読み取って、そこで左右に分けます【事実：`GeometryProxy.reservedRegions(kind:options:layoutDirectionBehavior:)`、iOS 27.1 以降 [A9][A10]】。開いているときは折り目の中心で分け、半分折ったときは折り目の範囲（余白こみ）に何も置きません。この計算は PetaCore の `PaneSplit` にあり、テスト済みです。【不明】実際の折り目の幅と、半分折ったときの見え方は実機・シミュレータで未確認。
- iPhone Duo の外側は iPhone と同じ1列で、選んだ月のパターンのまま出します（モックは点だけでしたが、帯も入るのでそのまま）。縦に並ぶバーは OS が自動で置きます（自動チェックの画像で確認済み）。
- 「今月の合計」はモックでは題名の横（iPad）や月の下（Duo）でしたが、実装はどの端末でも月の上の1行です。
- iPad のキーボード：⌘N 記録を追加、⌘E 予定を追加、⇧⌘N 文章から予定をつくる、⌘T 今日、⌘F 検索、⌘1〜⌘4 タブ。⇧⌘V は見送り（一覧を参照）。
- Mac：サイドバーは カレンダー／記録／集計／検索 と「表示するカレンダー」。モックにあったツールバーの検索欄と「AI取り込み 残り○回」は未実装（検索はサイドバーから）。予定の編集は、Mac には標準の編集画面が無い【推測：EventKitUI が macOS に無いため】ので、自前のフォームです。ウィンドウの最小は 800×560pt。

S-09〜S-14 の iPad・Mac・iPhone Duo 内側での見え方：どれもシート（iPad はフォームシート、Mac はウィンドウのシート、Duo 内側は中央のシート）の中に iPhone と同じ並びで出します。S-10・S-11 は、広い画面では一覧（左）＋詳細（右）の2列にします。**これらのモックは iPhone だけ描いています。**

### 5. アクセシビリティ
- VoiceOver（S-01 の1日）：「11月11日 水曜日 今日 予定2件 記録1件 プラス5,400円」。ロック中は「記録1件 ロック中」。
- 記録の行：「FX 午前の取引 収支 FX プラス5,400円」。
- 集計：「収支の合計 プラス6,600円 プラス2件 マイナス1件」。予算：「推し活の予算 15,000円のうち12,100円 81パーセント」。
- 記号だけのボタンにはすべて名前を付ける。まとめ画像には内容を読み上げる説明を付ける。
- 前後の月・週・日への移動（横のスワイプ、「前へ」「次へ」、「今日」、⌘ のショートカット）：今の画面と隣の月（週・日）が横に並んだまま指に合わせて動き、離すとそのまま隣の画面がすべって入る（約0.3秒）。「今日」で離れた月へ跳ぶときは、行き先の月を隣に並べてすべらせる。予定は前後の月の分も読み込んでおき、すべっている途中の隣の月にも予定が出る。40pt 以上か、勢いで画面の幅の3分の1を超えたら移動、足りなければ元に戻る。
- 視差効果を減らす：弾む動きを止める。前後への移動はすべらせず、短いフェード（約0.25秒）にする。透明度を下げる：バーを不透明に。コントラストを上げる：独自色を濃い値に。
- ジェスチャだけの操作はなし。

## C. Google カレンダーとの直接の連携（設計・2026-11-14・確認待ち）

### 1. 目的と範囲

- Google アカウントをアプリから直接つなぎ、Google カレンダーの予定を表示・追加・変更・削除する。**予定ごとの Google の色**（colorId）もそのまま出す（設定アプリ経由の今の方法では出せない）。
- 対象：iPhone／iPad／Mac（同じコード）。バージョン 1.1 で入れる（1.0 は審査中のため触らない）。
- 範囲外：Exchange／Outlook／Microsoft 365 の直接の連携（あとで同じ形で足す）、Google 以外の色の取り込み。

### 2. 技術の選び方

| 案 | 動作の軽さ | 配布サイズ | 作りやすさ | 対応OS | 将来性 | AI での書きやすさ |
|---|---|---|---|---|---|---|
| **A. 自前の OAuth（PKCE）＋ Google Calendar API（REST）** | ◎ 標準の部品だけ | ◎ 増えない | ○ ログインと通信を自分で書く | iOS／iPadOS／macOS（ASWebAuthenticationSession） | ◎ Google の公開の仕様 | ◎ |
| B. Google Sign-In の SDK | ○ | △ 増える | ◎ | iOS／macOS | ○ | ○ |
| C. 今のまま（設定アプリにアカウントを追加） | ◎ | ◎ | ◎ 作業なし | 全部 | ○ | ― |

**おすすめ：A**。理由：外部ライブラリを入れない決まり（CLAUDE.md）に合い、予定ごとの色が出せる。B は外部ライブラリになる。C は色が出ない。
- 根拠：iPhone アプリ用の Google の OAuth クライアントには秘密の鍵が無く、リダイレクトは Client ID を逆にした独自 URL スキーム（例 `com.googleusercontent.apps.<ID>:/oauth2redirect`）を使う（Google 公式「OAuth 2.0 for Mobile & Desktop Apps」https://developers.google.com/identity/protocols/oauth2/native-app 、AppAuth の Google 向けの説明）。
- 権限（スコープ）：`calendar.events`（予定の読み書き）と、カレンダーの一覧と色の読み取り用の読み取り専用スコープ。どちらも Google の分類で「センシティブ」で、一般公開には Google の確認（動画つき）が要る（https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification ）。一覧用のスコープの正確な名前は、作り始める前に Google の資料で確かめる（未確認）。
- 確認が済むまでは「テスト」の状態で、登録したテスト用のアカウント（本人）だけが使える。

### 4. 動き

- 予定の一覧・月の帯・週・日では、EventKit の予定と Google の予定を同じように並べる。Google の予定の色は、「予定ごとの色」がオンなら予定の colorId、オフならカレンダーの色。ユーザーが ColorStore で選んだ色があればそれを優先する（今と同じ）。
- 新しい予定・編集・削除：保存先のカレンダーが Google なら API で書く。終日・時刻・場所・メモ・色を扱う。
- 同じ Google アカウントが設定アプリにもあるとき：その EventKit のカレンダー（アカウント名がメールアドレスと同じもの）を隠して、二重に出さない。
- 読み込み：表示している月の前後1か月。画面を開いたとき、前面に戻ったとき、引っぱって更新したとき。変更の差分は syncToken で取る。電波が無いときは最後に読み込んだ予定を出し、一覧の上に「最後に読み込んだ予定を表示しています」。
- ログインの情報（リフレッシュトークン）はキーチェーンにだけ保存。開発者のサーバーは使わない。期限切れ・取り消し（invalid_grant）のときは S-16 の行を「ログインし直してください」にする。
- 接続を解除：トークンを Google で取り消し、キーチェーンと保存した予定を消す。Google 側の予定は消えない。
- 状態の保存：表示するカレンダーの選択と色の設定は端末に保存。
